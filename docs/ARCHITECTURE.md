# METEOR V1 — architecture for implementers

Rules and examples. Read `CLAUDE.md` first. Paths are repo-relative. "Base" means the Coucou fork that this tree started from.

## 2. The feature registry

A feature has two independent states: **enabled** (user switch, sparse: absent = default) and **running** (its Rust `start` succeeded). Disabled means `start` is never called: no thread, hook, timer, window or poller exists. Both sides have one object per feature.

### 2.1 Rust: `notch_core::Feature`

```rust
// crates/core/src/feature.rs
pub struct Manifest {
    pub id: &'static str,
    pub name: &'static str,            // English, translated through strings.json
    pub group: Group,                  // Island, Agents, Chat, Media, System, Input, Windows, Files, Capture, Apps, Tools
    pub default_on: bool,              // true for every feature in this fork (the original shipped opt-in tools as false); a feature still waits for a click before it uses the microphone, the camera or administrator rights
    pub uses: &'static [Use],          // Network, Microphone, Camera, Clipboard, InputHook, Capture, Elevation, FileDelete
    pub shortcuts: &'static [ShortcutDef],   // { id, label, default: Option<&'static str> }   e.g. ("toggle", "Open timer", Some("Ctrl+Shift+T"))
    pub tray: &'static [(&'static str, &'static str)],   // (item id, label)
    pub defaults: &'static str,        // JSON object: the feature's default settings
}

pub trait Feature: Send + Sync {
    fn manifest(&self) -> &'static Manifest;
    /// Called when enabled at launch or when switched on. Spawn everything here. Must be idempotent.
    fn start(&self, cx: &Ctx) -> Result<(), String>;
    /// Called when switched off and at quit. Must leave nothing running. Must be idempotent.
    fn stop(&self, cx: &Ctx);
    /// The feature's settings changed (already merged with defaults).
    fn settings_changed(&self, _cx: &Ctx, _settings: &serde_json::Value) {}
    /// Every command of the feature. Runs on a blocking thread; return fast, spawn long work and emit events.
    fn call(&self, cx: &Ctx, method: &str, args: serde_json::Value) -> Result<serde_json::Value, String>;
    /// `include_str!` of src/features/<id>/strings.json (the same file the TS side loads).
    fn strings(&self) -> &'static str { "{}" }
}

#[derive(Clone)]                       // cheap: move a copy into the tasks and threads a feature spawns
pub struct Ctx { /* app: AppHandle, host: &'static dyn Host */ }
impl Ctx {
    pub fn app(&self) -> &AppHandle;                                       // for what Ctx does not wrap (managed state, run_on_main_thread)
    pub fn settings(&self, id: &str) -> serde_json::Value;                 // defaults ⊕ stored
    pub fn patch_settings(&self, id: &str, patch: serde_json::Value);      // shallow merge, save, broadcast
    pub fn emit<T: Serialize + Clone>(&self, id: &str, event: &str, payload: T);  // "<id>:<event>" to all windows
    pub fn data_dir(&self, id: &str) -> PathBuf;                           // %LOCALAPPDATA%\meteor\features\<id>\, created on the way
    pub fn window(&self) -> WindowFactory<'_>;                             // §6
    pub fn paused(&self) -> bool;                                          // tray Pause (also `notch_core::paused()`)
}
```

`Ctx` reaches the app through the `notch_core::Host` trait, which `src-tauri/src/registry.rs` implements; features never see it.

Reserved `call` methods the host sends: `"shortcut"` with `{ "id" }`, `"tray"` with `{ "id" }`. A feature that needs neither ignores them (`_ => Err("unknown method")`). Both are also emitted to every window, as `<id>:shortcut { id }` and `<id>:tray { id }`. While a feature is not running the host refuses every `call` to it with `Err("<name> is turned off.")`.

Lifecycle in `src-tauri/src/registry.rs`: the list is `features::builtin()` (base adapters, hand-listed in `src-tauri/src/features/mod.rs`) + `features_gen::all()`, built before the app (their strings are merged into `i18n` and their ids allowed as secret prefixes at that point). At launch, in `setup`, after the settings window is created and before the island is shown (Tauri creates the island window itself from `tauri.conf.json`): for each feature `if enabled(id) { start }`. `feature_set_enabled(id, on)` → `start`/`stop` → save → emit `features-changed { id, on }` → the tray menu and the shortcut registrations are rebuilt; the settings sidebar rebuilds from the event. When a feature stops, the host also closes any window of it that is still open. At quit every running feature gets `stop`.

Threads: `start`, `stop`, `call` and `settings_changed` never run on the main thread inside a Tauri command. The host commands are async and hop to a blocking thread, as do shortcut presses and tray clicks; the one exception is `start` at launch, which runs in `setup`. This is what makes opening a window from them safe (§6).

Shortcuts: the host registers `Manifest.shortcuts` through `shortcuts.rs` while the feature runs, under the id `<feature>:<id>` (the key in `Settings.shortcuts` for a user binding, and the id in `shortcuts_status`); user bindings override defaults, `default: None` stays unbound, conflicts show "in use" in Settings. Defaults taken so far, the island's own included (a new one must not repeat any): Ctrl+Alt+N (open or close the island, off by default), Ctrl+Alt+Space (chat), Ctrl+Alt+A (waiting card), Ctrl+Alt+T (terminal), Ctrl+Alt+F (reserved), Ctrl+Alt+Right and Left (next and previous pill), Ctrl+Alt+S (mute the sounds); Ctrl+Alt+V and Ctrl+Alt+Shift+V (`clipboard`: history, paste as plain text), Ctrl+Alt+O and Ctrl+Alt+U (`audio-mixer`: next output, mute all microphones), Ctrl+Alt+PageUp and PageDown (`displays-keepawake`: brighter, dimmer; its keep-awake toggle is unbound); Ctrl+Alt+Shift+4 and Ctrl+Alt+Shift+3 (`capture`: the selector, the whole screen); Ctrl+Alt+Shift+5 (`recorder`: start or stop a screen recording); Ctrl+Space (`command-bar`); Ctrl+Alt+L (`input-tools`: the snippet library); Ctrl+Alt+R (`radial-menu`: the first wheel); Ctrl+Alt+B (`companion`: home or out); Ctrl+Alt+Win+Left, Right, Up, Down, Home, Backspace, PageDown and PageUp (`window-layout`: the four halves, centre, put back, next and previous display; Ctrl+Win+Left and Right are Windows' own). Unbound by default: the timer toggle, add a reminder, the capture tools (colour, text, ruler), draw and scrolling capture (`editor`), record the window in front and pause or resume the recording (`recorder`), the second and third wheel, hold to dictate (`dictation`, the setting `hold`), and the three of `misc-late` (demo, cleaning mode, add the Explorer selection to the shelf). A press sends `call("shortcut")` and emits `<id>:shortcut { id }`. The island's own actions (`ACTIONS` in `shortcuts.rs`) keep their bare ids; the three that belong to a built-in feature (`openChat` → chat; `goToAlert`, `jumpToTerminal` → agents) are released while that feature is off; `nextTab` (the next tab of the island) is the one action without a default key.

### 2.2 Host commands (the only Tauri commands a feature uses)

| Command | Purpose |
|---|---|
| `feature_call { feature, method, args } → Value` | routed to `Feature::call` on `spawn_blocking`; an error while the feature is off |
| `feature_settings { feature } → Value` | defaults ⊕ stored |
| `feature_patch_settings { feature, patch }` | shallow merge, atomic save, broadcasts `settings-changed:<id>` with the merged value, then `Feature::settings_changed` if it runs |
| `feature_set_enabled { feature, on }` | start/stop, saves the switch, broadcasts `features-changed { id, on }`; fails with what `start` reported (the switch stays on, `running` is false) |
| `features_list → [{ id, name, group, defaultOn, on, running, uses, shortcuts: [{ id, label, default }], tray: [{ id, label }] }]` | what Settings and the command bar render; `group` and `uses` are camelCase strings (`"agents"`, `"inputHook"`) |

Base commands (`boot`, `save_settings` for core keys, `open_url`, secrets, hooks…) stay as they are; the ones that belong to a built-in feature (`chat_send`, `chat_models`, `ingest_file`, `refresh_integration`, `github_refresh`) are refused or do nothing while that feature is off. Core settings keep the `Settings` struct; `Settings.features: BTreeMap<String, Value>` (only what differs from the manifest defaults) and `Settings.enabled: BTreeMap<String, bool>` are Rust-owned (what a webview sends in `save_settings` is ignored for those two keys). Secrets: a feature stores keys with `secret_set` using the key name `<id>/<name>` (name: letters, digits, `-`, `_`); `notch_core::secrets` accepts any key with a registered feature's prefix.

### 2.3 TypeScript: `defineFeature`

```ts
// src/core/registry.ts — the only file with import.meta.glob; nothing else imports features directly
const modules = import.meta.glob("../features/*/index.ts", { eager: true });
const strings = import.meta.glob("../features/*/strings.json", { eager: true });
export const FEATURES: FeatureModule[] = Object.values(modules).map((m) => (m as { default: FeatureModule }).default);

// src/core/feature.ts
export interface FeatureModule {
  id: string;
  /** Coucou pill catalog entry (agent-style features only). */
  pill?: PillDefinition;
  /** Compact-strip live activities (§5). */
  activities?: ActivityDef[];
  /** Expanded-island sections (§5). */
  sections?: SectionDef[];
  /** Settings page body; the on/off switch is rendered by the host above it. */
  settings?: (cx: FeatureCtx) => HTMLElement;
  /** Floating window pages, mounted by window.html?feature=<id>&page=<name> (§6). */
  windows?: Record<string, (root: HTMLElement, cx: FeatureCtx) => void>;
  /** Command-bar rows (consumed by the command-bar feature). */
  commands?: CommandProvider;
  /** Global shortcut handlers by id, for shortcuts declared in the Rust manifest. */
  shortcuts?: Record<string, (cx: FeatureCtx) => void>;
  /** What can be said to the feature (docs/VOICE.md §5): `voice: () => import("./voice")`, read by the voice feature only. */
  voice?: () => Promise<{ default: VoiceAction[] }>;
  /** Runs when the feature is on and the island page has booted; return a dispose fn. Nothing runs at import time. */
  start?: (cx: FeatureCtx) => (() => void) | void;
}
export interface FeatureCtx {
  id: string;
  call<T>(method: string, args?: object): Promise<T | null>;          // feature_call; null when it failed (logged) or the feature is off
  on<T>(event: string, fn: (p: T) => void): () => void;               // listen("<id>:<event>")
  settings: { get(): Promise<Value>; patch(p: object): Promise<void>; onChange(fn: (v: Value) => void): () => void };
  island: IslandApi;                                                  // notice(), reveal(), open(section), activityChanged(), redraw(), fullscreen(), hold() → release fn (§5.3)
  t: typeof t;                                                        // i18n, feature strings merged
}
```

`src/core/feature.ts` also holds the surface types (`ActivityDef`, `SectionDef`, `SectionHost`, `Notice`, `NoticeKind`, `IslandApi`, `CommandRow`, `CommandProvider`) and `defineFeature`. `src/core/registry.ts` is the runtime: `startFeatures()` (called once by the island page after boot: runs `start` of every feature that is running in Rust, wires `shortcuts`, and follows `features-changed` with start/dispose), `featureCtx(id)`, `featureById(id)`, `featureOn(id)` (the gate for every surface a feature owns), `featureInfos()`, `onFeaturesChanged(fn)`, `loadFeatures()` (for windows other than the island; safe to call more than once), and `setIslandApi(make)`, which the island shell calls with a function from a feature id to that feature's `IslandApi`: `cx.island` is scoped, so `open("timer")` and `activityChanged("running")` name the feature's own section and activity by their ids. In every other window `cx.island` stays the inert default.

**Voice actions** (`docs/VOICE.md` §5). A feature says what can be said to it without knowing the voice assistant exists: its actions are a list in `src/features/<id>/voice.ts`, which ends with `export default defineVoice([…])`, and one line in its `index.ts`, `voice: () => import("./voice"),`. Each `VoiceAction` has an `id`, the `tool` name the action model sees, one `describe` line, the `forms` that are said (`"set a timer for {minutes}"`; words in order, `[x]` optional, `(a|b)` alternatives), its `args` (`number`, `minutes`, `percent`, `time`, `text`, or `choice` with a live list), its `safety` class (`run`, `confirm`, `prepare`), `run(args, v)` answering a `VoiceReply` (`say`, `show`, `ask`, `ok`) and an optional `undo`. `run` gets a `VoiceCx` (`call`, `t`, `open(section)`), not the feature's context: its `call` reaches the action's own feature through the voice runner's deny list. The types, `defineVoice` and the pure `collectVoice(features, on)` are in `src/core/feature.ts`; `voiceActions()` in `src/core/registry.ts` is the lookup the voice feature calls, at its start and after `onFeaturesChanged`. A feature that is off contributes nothing, and a `voice.ts` is a chunk of its own that is not loaded before voice first asks.

Rules: `index.ts` has no side effects at import (a disabled feature loads nothing). A feature does not import another feature, with one kind of exception: a feature that is built on another may call a named export of that feature's `index.ts`. `lyrics` does, handing the line being sung to `media` with `setLyric(text, note?)`; the export must work whichever of the two is off. All DOM is built with `h()` from `src/views/dom.ts` and the classes in `src/ui/components.css`. CSS lives in `src/features/<id>/style.css`, imported by `index.ts`, every selector prefixed `.f-<id>-`. Strings: `src/features/<id>/strings.json` in the `extra.json` format (English key → 10 languages); the TS registry merges them into the i18n table at boot and Rust merges `Feature::strings()` at launch, both language by language: an entry in English only never takes away the translations another table has for the same English text. A missing language falls back to English, so a feature ships English first and the other languages follow. Every text a feature shows needs a key, the manifest's `name` and its shortcut and tray labels included (Settings shows them through `t()`). A count goes through `tn(one, other, n, vars)` or carries `count` in its variables: the plural form is picked from `count`, never from `{n}`.

### 2.4 Minimal complete example

Feature `timer` (shortened). Generated by `node scripts/new-feature.mjs timer`.

```rust
// crates/timer/src/lib.rs
use notch_core::{Feature, Manifest, Ctx, Group, Use, ShortcutDef};
static MANIFEST: Manifest = Manifest {
    id: "timer", name: "Timer", group: Group::Island, default_on: true, uses: &[],
    shortcuts: &[ShortcutDef { id: "toggle", label: "Start or stop the timer", default: None }],
    tray: &[], defaults: r#"{ "lastMinutes": 25, "sound": true }"#,
};
#[derive(Default)] pub struct Timer { state: Mutex<Option<Running>> }
impl Feature for Timer {
    fn manifest(&self) -> &'static Manifest { &MANIFEST }
    fn start(&self, _cx: &Ctx) -> Result<(), String> { Ok(()) }               // nothing runs until a timer starts
    fn stop(&self, _cx: &Ctx) { self.state.lock().unwrap().take(); }         // aborts the tokio sleep (drop)
    fn call(&self, cx: &Ctx, method: &str, args: Value) -> Result<Value, String> {
        match method {
            "start" => { /* spawn one tokio sleep to the deadline; at the end cx.emit("timer", "done", {}) */ Ok(json!({})) }
            "cancel" => { self.state.lock().unwrap().take(); Ok(json!({})) }
            "shortcut" => self.call(cx, "start", json!({ "minutes": 25 })),
            _ => Err("unknown method".into()),
        }
    }
    fn strings(&self) -> &'static str { include_str!("../../../src/features/timer/strings.json") }
}
pub fn feature() -> std::sync::Arc<dyn Feature> { std::sync::Arc::new(Timer::default()) }
```


## 3. Auto-discovery and the generator

**Rust.** `src-tauri/build.rs` reads `src-tauri/Cargo.toml`, takes every `[dependencies]` key starting with `notch-feat-`, and writes `$OUT_DIR/features_gen.rs`:

```rust
pub fn all() -> Vec<std::sync::Arc<dyn notch_core::Feature>> { vec![ notch_feat_timer::feature(), notch_feat_media::feature(), … ] }
```

`src-tauri/src/registry.rs` does `mod features_gen { include!(concat!(env!("OUT_DIR"), "/features_gen.rs")); }`. The scan is line-based (no TOML parser): one feature per line, in the form the generator writes. `cargo check -p notch-feat-<id>` checks a feature alone; `cargo check -p meteor` checks the app with every registered feature.

**TypeScript.** `src/core/registry.ts` globs `src/features/*/index.ts` and `*/strings.json` (§2.3). Vite resolves the glob at build time; nothing is listed by hand. `import.meta.glob` is unavailable under `node --test`; tests never import `registry.ts`.

**`node scripts/new-feature.mjs <id> [--service <name>]`** creates, from templates in `scripts/templates/`:
- `crates/<id>/Cargo.toml` (`name = "notch-feat-<id>"`, deps `notch-core`, `serde`, `serde_json`, `tauri`, an empty `windows` feature list the feature edits), `crates/<id>/src/lib.rs` (a `Feature` stub whose `start` is a no-op, whose `call` answers `Err("unknown method")`, whose `strings()` includes the TS side's `strings.json`, and whose manifest has `group: Group::Tools` and `default_on: false` until the feature edits them);
- `src/features/<id>/index.ts` (`defineFeature({ id })` with no surfaces), `style.css` (a comment), `strings.json` (`{"strings":{}}`), `tsconfig.json` (extends the root config; includes `src/core src/ui src/views src/island src/i18n src/settings src/window src/mascot src/recap src/upload src/*.ts` and `./**/*`, so `npx tsc --noEmit -p src/features/<id>` ignores every other feature);
- with `--service <name>`: `crates/svc-<name>/{Cargo.toml,src/lib.rs}` (package `svc-<name>`, a plain lib depending on `notch-core`, not a feature);
- and edits **exactly one shared file**: `src-tauri/Cargo.toml`, adding `notch-feat-<id> = { path = "../crates/<id>" }` right under the `notch-core` line (feature lines kept sorted). `Cargo.toml` at the root globs `crates/*`, so nothing else changes; `Cargo.lock` follows at the next cargo command. It refuses an id that is not lowercase kebab, that already exists, or that is reserved (`core`, `brand`, `svc-*` and the built-in ids `agents`, `chat`, `integrations`, `drop`, `recap`). Run `cargo check --workspace` once afterwards so `Cargo.lock` is complete. To remove a feature: delete its two directories and its line in `src-tauri/Cargo.toml`.

A feature adds its own crate dependencies in its own `Cargo.toml` (`windows` crate features are unified by Cargo across the workspace: declare the ones you use, in your crate). A feature never edits `src-tauri/Cargo.toml`, the root `Cargo.toml`, `vite.config.ts`, `tauri.conf.json`, `capabilities/`, `src/style.css`, `src/i18n/*.json`, `src/core/*`, `src/ui/*`, `src/island/*` or another feature's directories; a change needed there is made in the shared file itself.

## 4. Island window and modes

One transparent, non-activating, topmost WebView2 window hung from the top centre of the chosen display, or wherever the user dragged it ("Dragged anywhere" below) (base `island.rs`; unchanged mechanics: `WS_EX_NOACTIVATE|TOOLWINDOW`, 60 Hz cursor poll parked when hidden and slowed to 10 Hz while a strip that stays rests, click-through from the pushed island rect; the keyboard by §4.1). Panel 720×360 logical, strip 240×6 when hidden.

**Hidden until needed is the only mode.** States (`src/island/fsm.ts`, base FSM renamed): `hidden` → `peek` (compact strip, 32 px) → `open` (expanded, 640 wide) and `greet` (launch, 1.6 s: the peek strip slides down and the mascot rises into its place on it; a pointer or a click during it is a pointer or a click on the strip; with the mascot hidden the launch is a plain 2 s reveal). Inputs and timings:

| Input | Effect |
|---|---|
| pointer enters the 240×6 wake strip | `hidden → peek` once it has stayed there 50 ms (a pointer that only crosses the top edge brings nothing out); stays while the pointer is on the island. An island that was put away under a pointer resting on that strip (Esc, the wheel, the shortcut, a jump to a session) brings nothing out until the pointer has left the strip (`Island.wakeSpent`): it would come straight back |
| pointer rests on the peek strip 250 ms, or clicks it | `peek → open` (hover-open is on by default; Settings › Island can turn it off; resting on a button of the strip opens nothing, so a notice's action, Pause and Stop of a recording and the fold mark are still there when the press comes: `fsm.overControl`), on the section of what the strip shows when that has one (a notice too: a hover opens the island while a HUD shows), else on the tab chosen in Settings › Island "Open on" (`openOn`, a section's key), else on the home view |
| pointer leaves | hover-opened: `open → peek` after 0.6 s; click-opened: after `autoClose` (15 s, 5–120); `peek → hidden` after 2 s, unless the strip stays (next row but one) |
| `reveal(ms)` from the arbiter (notice, activity change, agent work starting) | `hidden → peek` for `ms`, then back to hidden unless something holds or the pointer came; a notice's time replaces what an earlier reveal had left, an activity's extends it |
| Settings › Island "The small island stays" (`peekStay`; pure rules `stays`, `agentBusy` and `IslandStateMachine.kept` in `fsm.ts`, cases in `tests/island-stay.test.mjs`) | **For a moment** (`moment`, the default): the two rows above, nothing else. **While an agent is working** (`agent`): once out, the strip stays for as long as an agent session works or waits for the user (`working`, `thinking`, `searching`, `approval`, `question`, or the approval badge; a service's pill is not an agent), then leaves as above. **Until I dismiss it** (`always`): once out, by the pointer, a notice, an activity, the greeting or a fold from `open`, it stays at `peek`. A strip that stays is **put away** (`peek → hidden`, until it next comes out the usual ways) by Esc while the pointer is on it, by the island's own shortcut (`toggleIsland`: one step back, as Esc does; pressed again it opens the island), by the fold mark (a small chevron at the strip's right end, drawn while the pointer is on the strip and the row has no button of its own; resting on it does not hover-open) and, as before, by the wheel. Staying is not a hold: the full-screen rule, the tray's Pause, lock and sleep hide the strip as they always did, and a card that waits or a strip a feature holds is none of this setting's business (no mark, no Esc, nothing put away) |
| `alert(section)` (approval, question, tray Open, shortcut) | any → `open` on that section; `pinned` while a card waits |
| `hold(token)` / `release(token)` | a feature keeps the island from auto-hiding (drag in progress, share sheet, timer page open by click, camera on) |
| a press outside the open island (any button, any other window) | `open → peek` at once. Not a card that waits, not a pinned island (Ctrl+P), not one a feature holds (a drag, a share sheet); a key of an on-screen keyboard is not outside. The island never has the focus to lose, so the press is heard through `svc-input`'s mouse hook (`island::watch_outside`): the page asks for it only while the island is open and could fold (`set_outside_watch`), the subscriber never swallows and only notes the point, and the cursor poll, which knows where the island is, places it on its next tick and emits `outside-press` |
| the fold chevron (last button of the header) | `open → peek`; not there while a card waits |
| Ctrl+Tab, Ctrl+Shift+Tab | the next tab, the one before: Home, Chat, then the sections in their order. A base Ctrl key (§4.1): it works once the island holds the keyboard |
| the global shortcut "Next tab of the island" (`nextTab` in `ACTIONS`; no key until the user gives it one in Settings › Shortcuts) | the next tab, opening the island when it is shut |
| a click on text a card cut short (`.focus-line`, `.title`, `.detail`, or anything a feature marks `data-expand`) | the reader: all of that text, in the same letters and colour, over the view; a click or Esc puts it away. Never on a control, and never while a card waits (nothing covers its buttons) |
| Esc | steps back: reader → layer → section → peek; a waiting card folds to peek and stays pinned (a folded card is reopened by a click, never by hover). On a strip that stays, one more step: hidden, and only with the pointer on it (§4.1) |
| tray Pause | `hidden`, wake strip inert, pollers paused |

The keyboard has its own rules, §4.1; how the island opens and folds, §4.2. Wheel on the peek strip: down opens, up closes (one decision per 0.35 s sequence); Settings › Island "Wheel on the strip" (`wheelGesture`) turns it off. The window shrinks to the strip 420 ms after `hidden`, which parks the poll thread and stops the frame loop (base idle design, unchanged).

**A strip that stays rests.** The window cannot shrink while the strip is on screen, so idle is kept another way. When the setting keeps the strip out (`fsm.kept`), the pointer is away and nothing moves (no geometry, journey, greeting, drop sequence or dancing mascot), the page says so once (`set_poll_rest(true)`, `Island.setRest`). From then on: Rust's cursor poll ticks ten times a second instead of sixty, emits no `cursor` event and does nothing but look for the pointer coming back onto the island's shape, at which it ends the rest itself and is at 60 Hz again from that tick (the click-through and the key hook stay as the last full tick left them: clicks pass, no key is read); the page draws no frame at all when no mascot is on the strip (it is hidden in Settings, or an activity has the strip), and otherwise one about every 66 ms (`REST_FRAME_MS`, about fourteen a second) so the mascot still breathes. Any change (a notice, a state, the pointer) is drawn at once and ends the rest for as long as something moves. What the strip animates in CSS (a busy ring, playing bars) is the browser's and runs while it is shown. The cost of the slow poll: a click in the first tenth of a second after the pointer arrives on a resting strip can still go to the window underneath.

**Dragged anywhere** (Settings › Island "Let me drag the island", `islandDrag`, on by default; the rules are plain functions in `src/island/place.ts`, cases in `tests/island-place.test.mjs`; behaviour after upstream pull request 428). A press on the strip (not on a button of it) or on the empty part of the open header is a drag once the pointer has travelled more than 6 px with the button held (`dragStarted`); until then it is a click that has not happened yet: what the click does (open the strip, take the keyboard, §4.1 rule 3) runs when the button comes up where it went down, so with the switch on the strip opens on the release, and a drag never takes the keyboard. The page only recognises the gesture: it holds the island (`fsm.hold`: nothing folds or hides, a card that waits stays as it is and its buttons are never under the release, whose click is swallowed) and calls `island_drag`; the cursor poll, which runs anyway while the island is out, then does nothing but carry the window under the pointer every 8 ms and says `island-drop` with the window's top-centre point when the button comes up. No hook, no timer and no thread is added, and nothing of it exists while the island is hidden. The page then decides (`settle`): within 24 px of the top edge of the display the point is on (the nearest one when it is over nothing) the island **docks** there, hanging from the edge as before at that horizontal place, or at the middle when within 24 px of it; anywhere else it **floats**. Either way the whole open island (640×320) is kept on its display, inside the work area when floating (`kept`). The spot is saved as `islandSpot` (`{ display, x, y, docked }`: the island's top-centre point in logical pixels from the corner of the display named by the same key as `screen`, so it survives a change of scale) and resolved at start and whenever the displays change (`resolve`, `findDisplay`: the same key, then place and name, name and size, place and size, a unique name); a display that is gone gives nothing, which is the top centre of the display chosen in "Island lives on", and the spot is clamped again to the display of today, so it is never restored off screen. Rust knows only the result (`island_place`: the window's top-centre point in screen pixels and whether it floats; `apply_geometry` uses it instead of the top centre) and the display list it hands the page (`island_displays`). With no spot the window is placed by the code path it always was.

A **floating** island has all four corners round and the floating-window shadow and edge of §7 (`html[data-place="float"]`); it sits 12 px lower in its window (`FLOAT_TOP`: `#root` is moved, the cursor is measured from there in `Island.onCursor`, and the pushed rect says so to the click-through) so the shadow has room above. Hidden, it is a 72×14 pill at that place: the wake strip, drawn; the window shrinks to 80×30 around it and the poll parks exactly as on the edge. Wake, hover-open, the fold, Esc under the pointer and "The small island stays" are the same code at the new place. "Put the island back" (the tray menu, and Settings › Island) clears the spot, and so does choosing a display in "Island lives on". While the window is the panel a DOM `mouseenter` on the wake strip counts only if the cursor poll agrees: the web view keeps believing the pointer where it last saw it when a dropped window is put somewhere else than under the hand, and said "enter" each time the island retracted from that place. (debt: carrying the window across displays of different scales is untested; a hidden floating island whose display is unplugged is put back when it next comes out, or from the tray; the 12 px above a hidden pill take clicks.)

Fullscreen: when the foreground window covers its monitor (`svc-sysevents` foreground event + monitor rect test), the wake strip is inert and notices are queued; the next non-fullscreen foreground flushes them. The `huds-power` feature watches the foreground through `svc-sysevents` and tells the island with `cx.island.fullscreen(on)` (its setting "Stay away from full-screen apps"; while that feature is off the island never hides for a full-screen app). A card that waits, open or folded, is not hidden by it. Before a live activity brings a hidden island out (playback starting), the island asks the rule again (`huds-power` call `fullscreen`, which reads the window in front afresh): a window that went full screen without the event arriving is still stayed away from. Lock, sleep, display-off: `svc-sysevents` pauses features that subscribe. The island itself is told of lock and sleep by its own cursor poll, which emits `away` when the cursor cannot be read (the lock screen or a UAC prompt has the desktop; said again about twice a second while it lasts) or when a tick took more than five seconds (the computer slept): a strip is then put away like under a full-screen app (`Island.away`), never a card that waits. (debt: the host does not link `svc-sysevents`, whose `on_session` is the event itself.)

### 4.1 Keyboard

The user's own window keeps the keyboard unless they give it to the island. Four rules; every feature follows them.

1. **Appearing never takes the keyboard.** A hover, a notice, an activity, a card arriving or being reopened by code: the island's window is non-activating (`set_focusable(false)`, never a style set by hand: tao writes the styles again from its flags) and the user goes on typing where they were.
2. **Open, with the pointer over it, the island's own keys work without a click**, and do not also act in the window underneath. The island is not the active window then, so Rust reads them with a low-level keyboard hook (`src-tauri/src/platform/keyhook.rs`). The page says which combinations are the island's at that moment (`Island.islandKeys` → `set_island_keys`, pushed whenever the set changes): **Esc**; **Ctrl+K** while there is a gallery (in the chat it starts a new chat); **Alt+letter** of every section while `keyJumps` is on; and the **`keys` the section on screen declares** (`SectionDef.keys`: the clipboard's `ArrowUp`, `ArrowDown`, `Enter`, `Shift+Enter`). The hook swallows exactly those and sends each back as an `island-key` event; the page dispatches it as a `keydown` on `document.body` (`Island.islandKey`), so every listener on `window` hears it as if it had been typed there (`isTrusted` is false: never test it). A key read this way counts as a click for the state machine (a hover-opened island becomes an ordinary open one). Never read this way: a letter or a digit alone, and the base Ctrl keys (Ctrl+←/→, Ctrl+↑/↓, Ctrl+1–9, Ctrl+P, Ctrl+O, Ctrl+E, Ctrl+, and Ctrl+Tab): they are what the user types and edits with in their own window, and they work once the island holds the keyboard. One exception: while a **question card** with options is on screen, its own digits (1 to as many as it has options) and Enter are read for it (`ViewHost.keys`, `comboCodes(names, true)`), because its options are numbered as in the terminal; they count only while the pointer is on the card or the island has the keyboard by a click (§5.6). A permission card names no key and no key answers it. On the strip nothing is read, with one exception: while a strip stays by the setting (§4, `fsm.kept`) the set is Esc alone, so that the pointer on it and Esc put it away; with the default setting the set is empty on the strip as it always was.
   The hook exists only while it has something to do: the set is not empty (the island is open and not paused) **and** the cursor poll says the pointer is over the island. It lives on a thread of its own that does nothing else. It goes when the pointer leaves, when the island folds or hides (the set empties), when the window shrinks to the wake strip (`set_collapsed`), on `RunEvent::Exit`, and with its thread, by Windows, however else the process ends. Each key is checked again as it arrives: the pointer over the island, the island's window visible, the cursor inside that window, the island not itself the window in front. After a swallowed combination that had a modifier the hook sends the unassigned key 0xE8, so the window in front does not take the modifier's release for a command of its own (a bare Alt opens a menu bar).
3. **A click inside the island gives it the keyboard fully**, every time, wherever it lands (`mousedown` on the island; a click on the strip that opens it): text fields can be typed in, every key goes to the island. So does a shortcut that opens the island, and a view with a text field (the chat, the gallery, a section with `keyboard: true`) reached by a click or a key, never one reached by a hover. `platform::take_keyboard` lifts the non-activation, remembers the window in front, brings the island to the front and moves the focus into the web view. Two things there are load-bearing: the front is taken with `SetForegroundWindow` and, when Windows refuses, a mouse event that moves nothing first, **never tao's `set_focus`**, which, when Windows refuses, presses and releases Alt in the window in front to get there (a browser or an editor takes a bare Alt for its menu key, which left keys dead); and `focus_window` is an async command whose work runs on the main thread, outside the web view's own request callback.
4. **It goes back** to the window it was taken from, if that window is still there and the island is still the one in front; otherwise to the next window that takes keys, never left on a hidden island (`give_keyboard_back`). The hand-back is checked like the take (`bring_to_front`): Windows can refuse even the window in front, and a call that is only trusted leaves the island there with the keyboard for nobody. When: the island folds, hides or closes for any reason (`Island.setMode`, and once more in `set_collapsed`, whatever the page said); Esc at the top level; a card is answered; and a quarter second after the pointer has left the island, unless a text field has the text cursor or a button is held (the island stays open; under the pointer its keys work again by rule 2). Leaving means having been there: an island opened by a shortcut with the pointer elsewhere keeps the keyboard until it folds. A click outside is the user's own choice: the cursor poll sees another window in front (`keyboard_was_taken_away`), the island is non-activating again, the page is told (`keyboard-lost`), and the next click inside takes the keyboard anew. The same click folds the island (§4, a press outside); the window that was clicked keeps the keyboard.

A key typed into the open island starts the fold countdown again (`fsm.activity`). For a feature: listen with `keydown` on `window`; a field stops only the keys it uses itself (`stopPropagation` on every key of the chat field kept Esc from the island); a section that wants keys without a click names them in `keys` and nothing it does not use (they no longer reach the user's window); text entry needs the real keyboard, so a section with a field sets `keyboard: true` and relies on the click; nothing but the island calls `focus_window` or moves the foreground; a secondary window that must never activate reads keys through `svc-input` (§6).

### 4.2 Opening and folding

Strip to open and back is one movement. The preview page `dev/design.html` is the reference for its curves.

- **The shell** is the only thing laid out while it moves: width, height and corner radius from script (`Island.applyGeometry`), growing on the base `Spring`, shrinking on `--d-slow --ease-in-out`, its width always a whole number of device pixels each side (`pixelWidth`). Everything else moves by `transform` and `opacity`: the mascot's canvas is one size for good (128 px, the mascot is drawn in it at the size it has) and is moved by `translate` snapped to device pixels; the countdown bar is scaled; the drop layer is centred by CSS.
- **What both states show travels** from its old place to its new one. The mascot is one canvas, placed from the island's centre line (the strip and the open island are both centred, so a width that springs never moves it). A title or a cover is marked `data-shared="title"` or `data-shared="mark"` at both ends (`stripRow()` marks its title and a `mark` element; the pills strip and the overview mark the name; `media` marks its title and cover): when the island opens or folds, `src/island/travel.ts` puts a copy of the destination over the source, hides both real elements and moves the copy with the shell (the spring opening, the curve folding; the copy drops out of the row before it slides to its column, and the reverse folding, so it does not pass through the mascot). Only when both ends say the same words or show the same picture; anything else cross-fades. A shared element is a leaf: text, or a picture with at most a dozen parts and no canvas.
- **Opening**: what only the strip shows fades out where it stands in `--d-fast`. What is new comes in only once the shell has nearly settled: the header after `--d-settle`, the body `--d-stagger` later, each with the content cross-fade of §7 (`--d-base`). A mascot that was not on the strip is new content and comes in with the body.
- **Folding**: the header and the body fade out at once in `--d-fast`, where they stand; the shell shrinks; the strip's own content comes back after `--d-settle`, so it is never drawn over the body.
- The pointer is tested against the shape the island is heading for, and again whenever that shape changes under a pointer that rests (`Island.pointerCheck`): after Esc with the pointer on the body the strip hides by itself.

## 5. Island content model

Three layers, one arbiter (`src/island/arbiter.ts`, pure TS, no DOM):

1. **Cards** (base alert views: approval, question, finished, error). An approval or question forces `open`, pins the island and is **never covered** by anything else; notices and activities queue behind it. Several requests wait in a queue, first come first served, five at most, and the card shows the oldest with "1 of N" (§5.6). Nothing a feature does takes the island off a waiting card: `cx.island.open` is refused, a level goes to the header capsule, a file dragged onto the island is not taken, a window attached to the chat does not open the chat, and a full-screen app does not hide it. Only the user leaves the card (a tab, Esc to fold it) and only an answer or its timeout ends it.
2. **Compact strip** = what the peek state shows (`src/island/strip.ts`). Candidates in priority order: **notice** (transient HUD) > **activity** (live) > **pills** (the focused pill's mascot, name and current step, and a dot for each of the next four; with Settings › Island "Clock on the strip", `stripClock`, the time as Windows writes it and the day, "09:41 Sun 11", before the dots, drawn again on the minute by a timer that runs only while that strip is on screen). One row: left = mark (icon, tinted icon chip, art or the mascot), right = reading (level meter and number, bars, a value or a small button); a feature builds it with `stripRow()` from `src/ui/components.ts`. Widths are fixed: notice 380, activity 340, pills 288. The agents at work are themselves the activity of order 3, drawn as the pills strip, so a timer outranks them and they outrank music.
3. **Expanded island** = header + body. Header: tabs Home · Chat · Drop (base; each hidden while its built-in feature is off), then the first seven sections of the features that are on, in the default order `SECTION_ORDER` of `src/island/sections.ts` (Dashboard, Music, Controls, Clipboard, Timer, Calendar, Shelf, then Utilities, Captures, Mixer, Notes, Weather, Agents, Screen time, Reminders, Apps, System, Layout, Keep awake, Battery, Displays, Quick access, Media tools, Cleaner, Mirror, Wallpaper, Breaks; a section that is not listed follows them in registration order; the open one is added if it is further down; the user's own order and hide list in Settings › Island is not built yet), a gallery button when any section exists (Ctrl+K, except in the chat where it starts a new chat: every section as a tile in the same order, seven to a row, three rows on screen and the rest reached by scrolling the grid (a thin scrollbar says so), type to filter, Enter opens the first; Alt+letter jumps from anywhere in the open island; Settings › Island "Keyboard jumps", `keyJumps`, turns both keys off), plan pills, gear, the switch for the app's own sounds (a speaker: its tooltip says "METEOR V1 sounds on" or "off", it is red when off; not the system volume), and the fold chevron (not there while a card waits). Letters taken: a Apps, b Battery, c Calendar, e Reminders, f Weather, g Agents, i Mirror, j Media tools, k Keep awake, l Layout, m Music, n Notes, o Controls, p Captures, q Quick access, r Timer, s Shelf, t Screen time, u System, v Clipboard, w Wallpaper, x Mixer, y Displays, z Cleaner; Breaks has none; d Utilities and h Dashboard are the island's own sections (§5.5); no letter is left. Only the tab that is on shows its title. While a level notice fires with the island open, the header's right side shows the level capsule instead (boring.notch open HUD). Body: the active view (base `ViewHost` map) or section (`SectionHost`), 608 wide, `height − 56` tall. A section declares its `height` (160–320); the island resizes with the base spring.

The base views in the design language: the **overview** is the focused pill (mascot 58, name, current step, project) in a 184 px column, then the other four pills as a 2×2 grid of cards; a pill that has data of its own to show (a service's card, an open diff, plan usage) puts it between the two and the pills become a narrow column. **Alert cards** (approval, question, finished, error) are one tinted card: a first row with the mascot at 22 px, who it is and what is going on; the command or message; the buttons. The **chat** has no card: bubbles on the island, the field at the bottom with the mascot left of it.

### 5.1 Notices (HUD)

`cx.island.notice({ kind, title, detail?, level?, bars?, icon?, tone?, mark?, action?: { label, run }, section? })`. `section` is the id of one of the feature's sections: a click on the notice opens it. `bars` (`true` or `"paused"`) puts the playing bars at the right end, as the new-track notice does beside its cover `mark`. Kind decides priority and duration (Vorssaint table, verbatim):

| Priority | Kinds | Duration |
|---|---|---|
| 3 | `volume`, `brightness`, `mic` | 1.6 s |
| 2 | `capture`, `timer`, `watch` | capture 12 s, others 6 s |
| 1 | `battery`, `notification`, `accessory`, `agent` | 4 s (agent 5 s, notification 3 s) |
| 0 | `clipboard`, `download`, `track` | clipboard 2.5 s, download 6 s, track 3 s |

Higher or equal priority replaces; same kind is updated in place (no re-animation: a level's meter slides to its new value); a notice under the pointer is replaced only by the same kind or a higher priority, and does not expire while the pointer rests on it; level notices that moved less than a key step (2 %, the Windows volume step) within 2 s of the last report are silent; a change to or from 0 (mute) always reports. A level reads as a percentage ("60%", on the strip and in the header capsule); Settings › Island "Show percentage" (`levelPercent`) off takes the number away from the notices and the capsule and leaves the symbol and the bar. A notice reveals the island (`reveal(duration)`); a click opens the related section. Motion: in 120 ms (fade + 4 px drop + blur 4→0), out 220 ms.

Behind a card or an open island: while an approval or a question waits (open or folded), and while the island is open on anything, a notice is not shown. A level goes to the header capsule if the island is open and is otherwise dropped (late, it means nothing); any other notice waits (one at a time, by the same replace rule) and is shown when the island is next on the strip, unless it waited more than 30 s. Nothing is shown while the tray's Pause is on.

### 5.2 Live activities

`activities: [{ id, order, isActive(), render(): HTMLElement, mark?(): HTMLElement, section?, onClick?(), tick?: boolean, hold?: boolean }]`. `render()` returns the strip row (`stripRow({ icon | mark, tone?, title, detail?, level | bars | value | action })`). Fixed order across features: timer 0, watch 1, downloads 2, a microphone in use 2.5 (`huds-power`, `ORDER.micInUse`: a privacy indicator, so it owns the strip before the agents, whose dot rides beside it, and with `hold` it keeps the strip out for as long as the microphone is held, except under a full-screen app), agents 3, agent work 3.5 (`agent-usage`: turns of sessions the hooks do not report), microphones muted 3.7 (`audio-mixer`: while the app holds every microphone muted), a break −1 (`breaks`: before everything while it runs), a recording −0.5 (`recorder`, `ORDER.recording`: before a timer, with `hold`; its row has the time recorded, Pause and Stop, and nothing rides beside it), calendar-countdown 4, music 5, keep-awake 6, clipboard copies 6.5 (`clipboard`: half a minute after two quick copies), and the battery the strip rests on 7. The first active one owns the strip; a second active activity rides along as its `mark()` (22 px) on the left when the pair is supported (pairs, by order: timer+{downloads,agents,agent work,calendar,music,keep-awake}; microphone in use+{agents,agent work}; calendar+{downloads,agents,agent work,music,keep-awake}); an activity without `mark` is never a companion. A lyric line is not an activity of its own: `lyrics` hands it to `media` (§2.3), whose row shows it in place of the title while the song plays, so a new line never slides the island out. A click on the strip, or resting on it, opens `section` (an id of the feature's own); `onClick` replaces the click. An activity **reveals** the island for 3 s when the feature calls `cx.island.activityChanged(id)` while it is active (it started, the track changed, a download finished) **and it is the one that owns the strip**; otherwise the island stays hidden, so idle stays idle: an agent reveals the strip when its work starts, not for every tool it runs, and music that pauses behind a timer or behind agents at work brings nothing out. `cx.island.redraw(id)` draws the activity's row again where it stands and never reveals (a title that changed, a cover that arrived). `hold: true`, or Settings › Island "Keep live activities on screen" (`keepActivities`, off by default), makes an active activity hold the peek strip instead. `render()` is re-run on each `activityChanged`, and for an activity that sets `tick: true` the moment the strip comes up and once per second while it is on it; a feature must call `activityChanged` when `isActive()` flips, the island does not poll it.

### 5.3 Sections

`sections: [{ id, title, icon, letter?, height, keyboard?, keys?, build(cx) → SectionHost }]`, `SectionHost = { el, show(), hide(), sync(), command?(c) }`. `build` runs once, the first time the section is shown; `el` fills the content area (608 × `height − 56`). `show`/`hide` are the demand signals: a section that samples (system monitor, camera, equalizer) starts in `show()` and stops in `hide()`; the island calls `hide()` on every path that leaves the section (close, Esc, tab switch, collapse, the island hiding, the feature being switched off), from one place (`Sections.sync` in `src/island/sections.ts`). `sync()` runs on the island's dirty-flag frame like base views (after any `State.notify()`); a section that changes on its own events updates its own DOM. `keyboard: true` makes the island take the keyboard when the section is shown by a click or a key (never by a hover); the section focuses its field in `show()`. `keys` names the keys the section acts on that the island reads for it while the pointer is over it without the keyboard (§4.1): `"ArrowUp"`, `"Enter"`, `"Shift+Enter"`, never a letter or a digit alone; the section hears them as `keydown` on `window` like any other key. Esc inside a section calls `command("back")` first; a section that handled it returns `true`. A section or an activity that throws is logged and skipped; it cannot stop the island's frame loop. A section draws its texts when it is built, so a change of language throws every built section away (`Sections.rebuild`): each is built again, in the new language, the next time it is shown. A section that listens to its feature's events takes what it draws from the event itself: the listeners of one event are not called in the order they were added.

`cx.island` in full: `notice(n)`, `reveal(ms = 3000)`, `open(sectionId, { dragged }?)` (refused while a card waits for an answer; with `dragged`, said by a section that comes for what is being dragged toward the island, refused as well while the Drop tab is on screen: a file dropped there is the chat's), `activityChanged(activityId)`, `redraw(activityId)`, `fullscreen(on)` (§4), `inHeader(sectionId)` (that section is a tab of the header right now: the Controls rail leaves out a tile that would only jump to it), `mode() → "hidden" | "strip" | "open"` and `onMode(fn) → off` (what the island shows and when that changes: the lyric line asks), `close()` (folds the open island to its strip; refused while a card waits), `hold() → release`. A hold keeps the island from folding and hiding until released (a drag in progress, a share sheet); the holds of a feature that is switched off are released for it.

Three more are the voice assistant's (`docs/VOICE.md` §7.5, §7.6; the rules are plain functions in `src/island/voice.ts`, cases in `tests/voice-seams.test.mjs`). For any other feature, and while `voice` is off, each does nothing; what they set goes when `voice` stops (`Island.voiceGone`), and none of them costs a frame, a timer or a listener while nothing is asked.
- `ear(on, heard?)`: the microphone indicator of §12 rule 9, a 28 × 3 px bar of `--accent` at 70 % at the top centre of the island's window, bright (`--ink`) for 0.3 s when `heard`. It is an element of its own over the island (`#ear`), drawn by two styles and one timer, with `pointer-events: none`: the wake strip under it takes the pointer as before, it is no part of the rectangle pushed to Rust for the click-through, and no key is read for it. Hidden or out, docked or floating, the island shows it at its top edge; over an open island it lies on the header's top 3 px, never on a card.
- `shape(ask?) → { mode, width, height, top }`: the island's box in logical pixels, the size it is heading for (0 high when hidden), centred in its window, `top` under the window's top edge; the capsule goes 6 px under `top + height`, which is 6 px from the top when the island is hidden under a full-screen app. With `ask = { width?, changed? }` the voice row also asks for the width of the strip while its own activity has it (340 by default, kept between 240 and 380) and to be called with the new box whenever it changes; `null` withdraws the ask. It changes nothing about which row has the strip: a card that waits still beats every activity (§5).
- `face(face | null, level?)`: the face of the island's own mascot during a turn. `listening` and `talking` carry a level 0…1 and are handed to the engine as `BotEngine.voice = { face, level }` (drawn by the `voice-mascot` feature; an engine that does not know the property ignores it) and to the dot of a hidden mascot as `data-state` and `--level`; `thinking` (looking up and right) and `asking` are faces the engine has, held over its state; `wink` and `surprised` are played once. While a card waits for an answer the mascot keeps the card's face.

Dropped files: a section that is a drop zone takes the page's drag events itself (capture phase, so the base drop does not see them) and hands the dropped `File` objects to Rust with `chrome.webview.postMessageWithAdditionalObjects("<slug>-file-drop:<feature>", files)`. `src-tauri/src/webview_drop.rs` turns them into paths and calls that feature's `dropped { paths }` through the registry, off the UI thread; nothing else hears of them. The same message without `:<feature>` is the base drop (the `drop` feature, a `file-drag` event to the island). Text and links are read from the drop's `text/uri-list` and `text/plain` in the page. A file dragged to the top edge opens the shelf (`cx.island.open("shelf", { dragged: true })`) from any view but the Drop tab: there the base drop takes it and shows the drop card (Ask, Send by email, Cancel).

### 5.4 Pills

The base pill model is unchanged (`src/core/pills.ts`, catalog, main pill, up to 4 declared). A feature that is an agent source contributes `pill` and uses the existing `State.tasks` API. With the mascot hidden (Settings › Mascot), a pill is a coloured dot with a state ring. On top of the catalog pills, an agent that runs more than one session at a time gets one pill per session (§5.6): `AgentTask.family` names the catalog pill such a pill belongs to, and everything that asks "which agent is this" reads `familyOf(task)`, never the pill's id. A pill whose agent waits for the user (`needsYou`) carries an amber ring, on its card in the overview and on its dot on the strip. A service's pill (catalog category `service`) with nothing more urgent to say reads the latest of its own card under its name (`serviceLine` in `src/views/integrations.ts`, the last fallback of `taskLine`): one small function per service beside the card it summarises, from the data that card is drawn from and nothing fetched for it (GitHub: a failing default branch, else what waits for review, else the open pull requests, else the calm line; Vercel: the latest deployment's state and age; Resend: the latest email; Stripe: the balance; Notion: the page edited last; Cal.com: the next call). Not set up or a failed fetch is said in the bad tone as on the idle card; set up with nothing yet is "Connected". The small line under it (`metaLine`) never repeats that line and is left empty when a service's kind is all it would hold.

### 5.5 The island's own sections

Two sections belong to the island itself, not to a feature (`own()` in `src/island/sections.ts`, feature id `island`; the island hands in how each is built with `setBuilder`). They are sections like any other: a tab, a gallery tile, a letter, a choice of "Open on", a stop of Ctrl+Tab.

- **Dashboard** (`island.home`, Alt+H, first in the header; `src/island/home.ts`): the Home page of smart cards. Two cards, each with faces: the first holds **Now playing** (`media` `state`) and **Agents** (the focused pill at work and a dot for each other one); the second holds **Levels** (volume from `audio-mixer` `devices` and then the `huds-power:volume` event; the battery from `huds-power` `state`) and **Next event** (`calendar` `cards`, four hours ahead). When the page comes up each card shows the face that matters now (an agent at work, a track playing, an event of the coming hour or one that is on); after that the card is the user's: its dots change the face, and nothing flips under the pointer. A click on a face opens its page (Music, the overview, the Mixer or the Battery, the Calendar). Under the cards, a row: the section last opened (kept in the page's own storage) and a system readout (CPU and memory from `sysmon`, watched only while the page is up). A face whose feature is off is not there, a card without faces is not drawn, and Settings › Island "Dashboard cards" (`homeCards`) picks both cards, one of them, or Off (no Dashboard). Nothing runs unless the page is on screen: a 5 s refresh, two listeners and the monitor's watch start in `show` and end in `hide`.
- **Utilities** (`island.utilities`, Alt+D; `src/island/utilities.ts`): every shortcut action of the running features as a list (the feature's icon, what it does, the feature's name, its key if it has one). A click folds the island, so the window the user was in is in front again, and then runs the tool as if its key had been pressed (`feature_action` → `registry::notify`, only for what a running feature's manifest names).

### 5.6 Agent sessions, cards and the relay

What an agent may do on the user's machine is decided on a card, so three rules hold for every line here: **no key, timer, default or step of the queue ever answers a permission card**; **the relay never blocks an agent CLI**; **an agent's settings file is written only after a diff, a dated backup and a click**.

**The relay** (`hook/`, `meteor-hook`). One process per hook event: it reads the payload, maps it onto Claude Code's names (`normalize.rs`), caps every string (2,000 bytes; the edit strings of a finished edit and a Stop's `last_assistant_message`, 32 KB, are the two that are kept longer), hands one line to the app over the pipe, and prints the agent's reply (`reply.rs`). `exchange(pipe, line, waits, budget)` is the whole of its waiting: `NoServer` at once when nothing serves the pipe, otherwise `Sent(answer)`; only `PermissionRequest` waits, 110 s at most, and running out of time is `Sent(None)`: no decision, nothing printed, and the agent asks in its terminal. A decision is only ever what the app wrote after a click. `--launch` (launch.rs) is the opt-in below.

**Sessions** (`src/core/sessions.ts`, pure; the table is `State.sessions`). A session is an agent (`family`: its catalog pill, `integration_claude`, `agent_codex`…) and that agent's session id. The first session of an agent keeps the agent's pill; every other session running beside it gets a pill of its own (`session_<n>`, `State.upsertSessionPill`: the family's colour, named after its folder) until it ends. Twelve sessions at most (the thirteenth takes the place of the one heard longest ago); a pill stays between turns and goes at `SessionEnd`, or after thirty silent minutes (pruned at the next event of anyone, and by one timer when nobody speaks). `judge(session, event)` is the one place that decides what an event means for its turn:

| Verdict | When | Effect |
|---|---|---|
| `late` | a tool result, a subagent's event or a second stop after the turn ended; any event carrying an older turn id of an agent that numbers its turns (Codex's `turn_id`) | nothing at all changes |
| `sub` | an event from inside a subagent (`agent_id`) while its turn runs | a step ("↳ …"), never the session's last tool or last words |
| `open` | a prompt, a tool call, a permission request | the turn starts or goes on; a prompt the CLI wrote itself (`<task-notification>`) continues the same turn |
| `background` | a stop whose `background_tasks` is not empty | still working ("In background: N"); no card, no sound, and its requests stay |
| `finish` | the stop that ends the turn | the finished card and its sound, once |
| `quiet` | a second end of the same turn (it was woken after being announced) | the pill says finished; nothing is announced again |
| `end` | an interrupt, a `/clear` typed as a prompt, the session's end | the pill rests (or goes with its session), nothing is announced |
| `error` | `StopFailure` | the error card |

`SessionStart` with `source` `clear` or `compact` rests the pill too, with no sound and no reveal. A session heard for the first time is taken to be at work (only a turn seen to end is over), and an agent that never sends a prompt event (it only says it stopped) finishes every time. `Notification` with `permission_prompt` or `elicitation_dialog` (the agent asks in its terminal and there is no card here) puts the pill in `approval` or `question` and posts one `agent` notice ("Waiting for you"); `idle_prompt` is not a session that needs the user.

**Requests** (`src/core/approvals.ts`, pure; the queue is `State.approvals`, and `State.pendingApproval` is its head). A `PermissionRequest` is taken from the deployed relay only (`pipe.rs`), gets a random id, and enters the queue with its agent, session, turn and id. The first one comes up (`island.alert`); one that arrives behind it is acknowledged, keeps its place, and changes only the count on the card. A sixth is declined at once. Each has its own 110 s from its arrival. A request leaves the queue in exactly four ways, none of which is an answer unless the user clicked: (1) a click on the card, through `decideRequest` / `answerRequest` / `returnRequest` in `src/island/agents.ts`, which carry the id of the request the card was drawn for and do nothing when that request is no longer the one on the card; (2) its turn ended (`ApprovalQueue.ofTurn`: same agent, same session, that turn or an older one), and the relay is told "no decision"; (3) its tool ran or failed, so it was answered in the terminal (`answeredBy`: same agent, session, tool and target; a result that follows an answer given here settles nothing more); (4) its time ran out. A card that has just come up, or just moved up, ignores clicks and keys for 600 ms. Allow, Always and Deny carry no key hint, are out of the Tab order, and take only a click with a pointer press in it (`byPointer`: a click a key makes on a focused button, Tab then Enter or Space, has `detail` 0 and answers nothing, which once answered a card).

**The question card** (`src/core/question.ts`, drawn by `buildQuestion`; ported from the fork base's upstream pull request 335). `QuestionFlow` holds where the user is: one label per pick-one question, a list for a pick-several one, "Other…" for words (the questions answered so are listed in `other`, and the relay accepts free text for those only, as non-blank text, without passing `other` on), Back with the ticks of the question before. `questionKey(key, context)` is the one place a key becomes an action: 1–9 pick an option, Enter confirms a pick-several question, only on the question view, only while the pointer is on the card or the island has the keyboard by a click (`ViewActions.keysAllowed`), never in a text field, never with a modifier. For every other view it answers null.

**The finished card.** `AgentTask.finalText` is the agent's last message as it wrote it, `finalLine` the same on one plain line. One line is drawn with `renderInline` (text, bold, `code`, http and https links; a link that is not a web address keeps its words; everything is a text node, nothing is ever parsed as markup); an answer one line does not hold (`isLongAnswer`) is drawn whole with `renderMarkdown` in a box that scrolls, and the island grows to 300 px. Links open through `open_url`, which checks the scheme again. The button reads "Open Claude", "Open Codex", "Open Cursor", "Open Antigravity" or "Open terminal" (`sessionOwner(family)`), and `jumpToSession` asks `open_session { sessionId, path, owner }`: the window Rust found for the session from the relay's own ancestors (`session_window.rs`), then its tab in Windows Terminal (`registry::call(app, "misc-late", "terminal_tab", …)`, errors ignored), else the app named by `owner` out of the fixed list in `platform::open_owner` (brought forward when it runs; the Claude app started from its install path or its registered protocol; an editor by its own launcher on the session's existing folder), else the folder in VS Code. The window is brought forward the checked way (`platform::bring_forward` on `bring_to_front`, §4.1): a plain `SetForegroundWindow` is refused when this process did not have the last input, which is the case after the global shortcut and after a click whose island has already handed the keyboard back, and the editor then opened in place of the session's terminal. Nothing an agent wrote is ever started. The island folds after the jump; a row of the session list and the ↗ of the overview do the same.

**Session chips and the session list.** `AgentTask.mode`, `effort` and `model` are what the agent says it runs with (`permission_mode`, `effort`, `model` on hook events; the status line relay adds the model's id and name and the effort level to the one line it already sent, and nothing else). They are capsules under the focus column and on the finished card; a mode in which the agent no longer asks is red. With two or more sessions of the focused pill's agent, the overview's detail card lists them (`sessionTasks`: the ones that need the user first; state, project, last tool, model, and a count of those that need the user). A click on a row goes to that session.

**Starting with the agent** (opt-in, Settings › Coding agents, off by default). Turning it on is a change to Claude Code's `settings.json` like any other (`hooks::preview(install, launch)` and `write`: diff, dated backup, fingerprint, click): METEOR V1's own `SessionStart` and `UserPromptSubmit` commands gain `--launch`; installing the hooks again keeps it as it is. With the flag, a relay that finds the app closed at the start of a turn starts it (`launch::app`) after printing its reply and without waiting: the target is the app's own path, written by the app beside the relay (`app-path`, in the folder only the user can write), and it must be an absolute path to an existing file named like the app; the relay's own three handles are made non-inheritable first, so the agent is not left waiting on a pipe the app would hold. An app started so (`--auto-launched`) quits when `mayQuit` says so: ten minutes after any session last spoke, with no agent at work, no request waiting and the island hidden. A copy the user started never quits by itself.

**Not built.** A Windows notification when a card waits (the host's `windows` dependency lacks `Data_Xml_Dom` and `UI_Notifications`, and a toast is only attributed to an installed build); switching the permission mode from the Allow button (it changes what an agent may do without being asked, and needs a control of its own); `--launch` for the agents of `agents.rs`.

## 6. Windowing model (secondary windows)

The settings window (hidden at launch, 760×620, min 640×480) and every feature window come from one factory in `src-tauri/src/winfactory.rs`. The types a feature uses are in `notch_core` (a feature crate cannot depend on the app); the factory is reached with `cx.window()`:

```rust
#[derive(Default)]   // WindowSpec { label, feature, page, w, h, ..Default::default() }
pub struct WindowSpec { pub label: String, pub feature: String, pub page: String,
    pub w: f64, pub h: f64, pub frameless: bool, pub topmost: bool, pub no_activate: bool,
    pub exclude_from_capture: bool, pub transparent: bool, pub monitor: Monitor }
pub enum Monitor { Island /* default: the island's display */, Cursor, Primary }   // the window opens centred on it
impl WindowFactory<'_> { pub fn open(&self, spec: WindowSpec) -> Result<WebviewWindow, String>; pub fn close(&self, label: &str); }
```

`label`, `feature` and `page` are letters, digits, `-` and `_`. `open` on a label that already exists shows and focuses that window instead of creating one. `no_activate` also keeps the window out of the taskbar and Alt-Tab; `exclude_from_capture` is `WDA_EXCLUDEFROMCAPTURE`; `transparent` adds `&transparent=1` to the URL, which makes the page's body background transparent. The host closes every window of a feature when the feature stops.

Every feature window loads the same page, `window.html?feature=<id>&page=<name>`; `src/window/main.ts` boots the bridge, i18n and the registry and calls `FEATURES[id].windows[name](root, cx)`. It loads `src/ui/tokens.css` and `src/ui/components.css`. One Vite entry serves all of them and `capabilities/default.json` covers every window label, so adding a window edits no shared file. Chrome: `.win` (dark panel, radius 12, hairline border, 36 px drag row with title and ×) from `components.css`; frameless windows draw it themselves, decorated ones get the OS frame.

Windows are created lazily, when `open` is called. The base's note that a WebView2 window created after the island comes up blank was settled by the foundation spike (F1): it is a thread problem, not a timing one and not the browser arguments. A webview built on the main thread from inside a synchronous Tauri command runs inside another webview's message callback, which WebView2 does not re-enter: the builder never returns and the window stays `about:blank`. Built from an async command, a blocking task, `run_on_main_thread` or `setup`, a late window loads `window.html` normally. The registry keeps `start`, `stop`, `call` and `settings_changed` off that path (§2.1), so a feature may call `cx.window().open(..)` from any of them; never add a synchronous `#[tauri::command] fn` that opens a window. Every window still passes the island's `additionalBrowserArgs` (WebView2 has one environment per app). Windows that take text (command bar, scratchpad, snippet library) use the "take and return focus" pattern: Rust records `GetForegroundWindow()` on open, activates the window, and `svc-inject::ForegroundGuard` restores it before any synthetic input. Overlays that must never activate (radial menu, capture overlays, HUD surfaces) set `no_activate` and read keys through `svc-input`.

## 7. Design language

One product, dark everywhere (island, sections, floating windows, settings). Dark only; there is no light theme. The preview page `dev/design.html` shows this design language. For anything not listed here, the shipped `src/ui/tokens.css` and `src/ui/components.css` are the source of truth. Tokens live in `src/ui/tokens.css` and are the only colours, sizes and curves anyone uses; `src/ui/components.css` + `src/ui/components.ts` are the only buttons, switches, rows and cards. A feature that needs something new asks for it to be added to the shared set rather than inventing it.

**Colour** (`:root`): `--bg #000` (island body) · `--panel #0b0c0e` (windows, settings) · `--card #141518` · `--card-2 #22252c` (hover, tab-on) · `--hairline rgba(255,255,255,.10)` · `--outline rgba(255,255,255,.14)` (borders of windows and menus) · `--ink #f5f6f8` · `--ink-2 #c9cdd4` · `--dim #9398a1` · `--dim-2 #828791` · `--accent #8ea2ff` · `--accent-ink #0b0c0e` · `--ok #34d399` · `--warn #f5a524` · `--bad #f4505e` · `--info #22d3ee`. Pill colours come from the pill catalog. Text on accent is `--accent-ink`. Never hard-code a hex outside `tokens.css`.

**Type**: `--font` = "Poppins" (bundled through `@fontsource/poppins` in weights 400, 500 and 600, never loaded from the network), then system-ui, "Segoe UI Variable Text", "Segoe UI", … (base stack, keeps the non-Latin fallbacks); `--mono` Cascadia Mono. Scale: `--t-xs 11/14`, `--t-sm 12/16`, `--t-md 13/18` (default), `--t-lg 15/20`, `--t-xl 20/24` (px/line-height); weights 400 body, 500 labels, 600 titles (Poppins has Latin and Devanagari only: Cyrillic, Arabic, Bengali and Chinese are drawn by the system fonts of the stack); numbers `font-variant-numeric: tabular-nums` in readouts; letter-spacing 0 (0.02em for all-caps `--t-xs` labels only).

Island side inset 16, header height 40, section content budget = height − 40 − 16.

**Motion**: `--ease-out cubic-bezier(.2,.8,.2,1)`, `--ease-in-out cubic-bezier(.45,0,.2,1)`; `--d-fast 120ms` (hover, notice in), `--d-base 180ms` (content cross-fade: opacity + translateY 4 px + blur 4px→0), `--d-slow 340ms` (island shrink, window close), `--d-settle 200ms` (the island shell has nearly reached its new size: new content may come in) and `--d-stagger 40ms` (between two groups of new content: the tabs, then the body), both used by §4.2. Growth uses the base `Spring` (response 0.5, damping 0.72), shrink `--d-slow --ease-in-out`. Hover states: background to `--card-2` and ink to `--ink` in `--d-fast`. `prefers-reduced-motion`: springs become 180 ms ease, blur and translate are removed. Never animate `width`/`height` of content, only transform/opacity; the island shell is the one exception (it already does).

**Island shapes**: peek strip 288×32, corners 0 top / 14 bottom, widening to 340 (activity) or 380 (notice) with the spring; open 640×h, corners 0 top / 22 bottom; optional 1.5 px outline `rgba(255,255,255,.14)` (Settings › Island). ## 8. Shared services

Each service is one crate under `crates/svc-<name>/`, built by the first feature that needs it and extended afterwards by the one feature named as its owner in the table. Consumers add it to their own `Cargo.toml`. Every service is refcounted: nothing of it runs without a live subscriber (the handle returned by `subscribe` unsubscribes on drop).

## 9. The mascot

Internal id `sprite`, user-visible name "Mascot". Drawn in Canvas 2D by `src/mascot/engine.ts`, which keeps the base engine's public surface (`setState`, `triggerEmote`, `bodyColor`, `lookX/lookY`, `setDancing`, `update(dt)`, `draw(ctx, x, y, d)`, `busy`) so every call site (island canvas, mini pills, recap image, icon generator) keeps working. Everything under the surface is new; no base drawing code survives.

**Chosen design: the Visor** (candidate A of the design preview). The reference implementation is candidate A in `dev/design.js`; port that drawing and motion into the engine rather than redesigning it.

**Shape**: a round orb in the body colour (the pill colour; a neutral dark grey when none) with one dark band across its upper half. It is not a squircle or rounded square, and it has no eyes, cheeks, mouth or limbs.

**Face**: a single bar of light inside the band is the whole face. It slides toward `lookX/Y`, blinks, scans while working, and changes shape with the state (dots, an arc, a cross) as the preview shows for `idle`, `working`, `thinking`, `approval`, `question`, `error`, `finished` and `sleeping`, and for the emotes `love`, `surprised`, `proud`, `wink` and `happy`. The preview does not have these, so build them in the same language: `searching` the bar splits into two small dots that drift · `ratelimit` the bar dims to 50 % and droops · `dizzy` the bar spins a full turn in 0.8 s · `yawn` the bar thins and the body stretches slightly taller · `annoyed` the bar tilts and the body shakes 3 times by 2 px. Interaction keeps the base behaviour: hover → `love` after 1.9 s, three clicks → `dizzy`, drag-out for window attach. The app and tray icons are generated from this face.

**Outside the island** (`src/island/tray-mascot.ts`, `src-tauri/src/tray.rs`, `brand_icon.rs`). The mascot that stands for the product wears the colour of the VS Code pill (`integration_claude`): the user's when they picked one, else the catalog's, which is also the colour of the icon the program carries (`scripts/gen-icons.mjs`). The island's page draws it with a `BotEngine` of its own and hands the pixels to the host: nothing is drawn a second time in Rust. *The tray*: it shows the face of the island's mascot. At rest it is one still picture, with a blink every six to ten seconds (the only timer); it moves, six frames a second, only while an agent works or waits for the user or a notice is up, and a frame is sent only when it differs from the one shown. Paused, nothing is sent; locked, it stops moving (the host answers that it cannot see the desktop) and a change of state still sends its one still picture. "Animate the tray icon" off, or the mascot hidden: one still resting face. At 16 px (100 % scale) the engine's drawing does not hold, so the tray gets the body and the visor only, on whole pixels; from 20 px it is the engine's. *The windows*: the taskbar button of every window of METEOR V1 wears the same still mascot, at creation and when the colour changes. *The shortcuts*: the icon inside `meteor.exe` cannot change at run time, so with a colour of the user's own the page makes an `.ico` (16 to 256 px), the host writes it to `%LOCALAPPDATA%\meteor\icons` and points METEOR V1's own shortcuts at it (`shortcut_rule.rs`: `METEOR V1.lnk` in the user's Desktop and Start menu Programs folders, while it starts this program and its icon is the program's own or one METEOR V1 wrote), behind "Use this colour for METEOR V1's shortcuts too". With the catalog's colour no shortcut is opened.

**Sizes**: Ø 58 in the open island, 28 in the peek strip, 20–24 as mini pills (body + eye bars only). **Hidden**: Settings › Mascot "Show the mascot" off replaces every mascot the island draws with a 10 px dot in the pill colour with a 2 px state ring (`--warn` approval, which pulses, `--info` question, `--bad` error, `--ok` finished) and, as in the preview, an arc in the pill colour that turns while it works or thinks (`dotMark` in `src/ui/components.ts`). The drop sequence's canvas and the recap image still draw the mascot. The greeting (`greet` state, 1.6 s): the strip slides down, the body rises from below with a 0.5 s spring and blinks twice. The wardrobe and the desktop companion are built on this engine (`src/mascot/outfits.ts` draws accessories as extra paths, never bitmaps).

**Voice faces** (`docs/VOICE.md` §7.6). The island hands the engine of its own mascot what the voice assistant asked for with `cx.island.face` (§5.3): it sets `engine.voice` to `{ face: "listening" | "talking", level: 0…1 }` or to `null`, and writes the same on the dot of a hidden mascot as `data-state="listening" | "talking"` and the CSS variable `--level`. Until the engine and `dotMark` draw the two faces, nothing reads either and the mascot keeps the face of its state; the island needs no change when they do.

## 10. Sound design

## 11. Hardware helper and the elevation boundary

The app never elevates. One process does, after two explicit consents: `helper/` is a .NET 8 self-contained console app `meteor-hw.exe` built on LibreHardwareMonitorLib with PawnIO (no WinRing0; `IsCpuEnabled/IsMotherboardEnabled/IsControllerEnabled/IsStorageEnabled/IsGpuEnabled` only), `requestedExecutionLevel=requireAdministrator`. The app launches it with `ShellExecuteExW("runas")` when the user turns on Settings › Hardware sensors (consent text names LibreHardwareMonitor and PawnIO; third-party libraries may be named); without PawnIO installed it offers `winget install namazso.PawnIO` or runs the official installer after a pinned SHA-256 check; the driver is never bundled, never auto-removed. Optional "start automatically" creates one Task Scheduler task (`RunLevel=Highest`, logon trigger, this user) during a consented elevation.

Pipe `\\.\pipe\meteor-hw-<userSid>-<random>` created by the helper with a DACL for the launching user's SID (+ SYSTEM, Administrators), `PIPE_REJECT_REMOTE_CLIENTS`, first-instance flag, message mode. On connect the helper checks `GetNamedPipeClientProcessId` → image path equals the parent path it was given, and the parent PID is alive; the app checks the helper's path and PID. Protocol: newline-delimited JSON, `{ "v": 1, "op": … }`: `hello`, `snapshot` (sensors with id, hardware, type, value, min, max, readAtUptimeMs), `subscribe { ms }` (helper polls LHM only while subscribed, ≥ 1 s), `reopen` → `{ inUse }` (closes the hardware and opens it again in the same process, so a PawnIO driver installed while the helper runs is taken up without a second prompt; at most every 5 s, else `too soon`; the helper also does it by itself at the first reading after the driver answers), `fan.apply { mode, level, curve }` validated by a `FanPolicy` inside the helper (PWM floor 20 %, thermal override at 85 °C, heartbeat timeout 10 s restores auto), `fan.heartbeat`, `fan.restore`, `quit`. The helper exits after 30 s without a connection and no manual fan mode; restores fans on any exit; `Computer.Reset()` after resume. What goes through the helper: CPU and motherboard temperatures, fans, package power, SMART. Everything else (GPU via NVML/ADLX, battery, thermal zones) stays in the unelevated app. The same boundary rule covers every other one-shot elevation (cleaner roots under Program Files, uninstalling per-machine apps, killing elevated processes): a separate `runas` relaunch of `meteor.exe --elevated-task <json>` that re-validates its allow-list and exits; never a service, never a persistent elevated listener.

## 12. Privacy and security rules (hold from the first version)

1. Secrets only in Credential Manager (`notch-core::secrets`), never on disk, never returned to a webview (`secret_present` only).
2. Network calls only to endpoints the user configured, plus opt-in third-party calls off by default: LRCLIB lyrics, the price list for usage estimates, update checks, and the speech model that dictation downloads when the user clicks its button (pinned revision, SHA-256 checked); and for voice (`docs/VOICE.md` §8), each only after the user's click or switch: the action model, the natural voice and the local text model (SHA-256 checked before kept and before run); Open-Meteo weather for the city typed; a free online text model and a free lookup service, each a switch that starts off; an online text model or voice with the user's own key. Every client is `net::bounded_get` (HTTPS, size cap, timeout), or `net::bounded_get_following` for an address that is known to redirect (https at every hop). No telemetry, no account.
3. A feature declares `uses` in its manifest; Settings › Privacy lists what each running feature can do (microphone, camera, clipboard, input hook, capture, network, elevation, file deletion). Nothing is used that is not declared.
4. Nothing the user types in the command bar, chat field, snippet buffer or scratchpad is logged; clipboard history skips `ExcludeClipboardContentFromMonitorProcessing` / `CanIncludeInClipboardHistory=0`, password fields and a secret-looking heuristic; the inbox, captures and history files live under `%LOCALAPPDATA%\meteor\`.
5. Agents are never auto-approved; the relay prints nothing unless the user clicked; agent CLIs are never blocked (timeout ladder 0.8 s < 108 s < 110 s < 120 s stays ordered). A decision is tied to the request the card was drawn for; no key, timer or step of the approval queue answers a permission card (§5.6).
6. Every write to a foreign config file: diff, dated backup, fingerprint, explicit click (`config_file`). Every deletion: review list, explicit confirm, Recycle Bin through `svc-fs::recycle` (permanent delete is a labelled mode for regenerable caches and the Empty Recycle Bin row only). Automated runs act only on rows a manual scan would pre-check and never elevate.
7. Synthetic input and hooks: `svc-input` suspends injecting subscribers while the foreground process is elevated; `svc-inject` refuses elevated targets; nothing is injected while the shortcut recorder runs.
8. The island, HUDs, capture overlays and the recording indicator carry `WDA_EXCLUDEFROMCAPTURE` (island only while hosting capture controls, otherwise per Settings › Island "Show in screenshots").
9. The camera starts only from a click and stops on every hide path; the LED must go off when the section hides. The microphone is opened in two ways only. (a) For one recording, by a click, a shortcut or the talk key (dictation, a push-to-talk turn), closed when that recording ends; and while the voice assistant itself is speaking, for the one word "stop" (nothing else heard then is kept or acted on), closed when it has finished. (b) Continuously, by the voice assistant waiting for its wake phrase, only while the user has switched `voice` on and "Listen for the wake phrase" on (off by default), and none of these pauses it: the tray's Pause, lock, sleep, display off, energy saver, a full-screen app in front, dictation or a recording using the microphone, every microphone muted. Whenever the app holds the microphone open an indicator is on screen the whole time (the bar of light on the rest strip while it waits, `IslandApi.ear`; the listening row and the capsule's dot during a turn); if the indicator cannot be shown the microphone is not opened. Audio stays in memory, and for one engine run in a temporary file deleted when the run ends; it never leaves the PC, is never logged, and no transcript is logged. A webview is given the camera only (`webview_permission.rs`, §8: the app's own pages, while the feature that shows it runs), never the microphone: dictation and voice record in Rust.
10. Pipes carry the user SID; both relay and helper verify the peer process; `open_url` is http(s) only; paths from hook payloads are never launched by type. "Open" on a session goes to a window found from the process tree or to a program out of a fixed list, and the relay's opt-in `--launch` starts only the app's own executable (§5.6).
11. System settings the app changes (active window tracking, pointer acceleration, lid action, Bluetooth, default audio device, session volumes, mic mute) are journaled first (`storage` journal), restored on quit and at the next launch.

## 13. The name

The product is **METEOR V1** (slug `meteor`). It was built under the code name "notch"; version 1.0.0 was renamed before the first public build.

**Display name and slug.** The name people see is `NAME = "METEOR V1"` (this fork's name) and the slug is `meteor`: it names the files and programs (`meteor.exe`, `meteor-hook.exe`, `meteor-hw.exe`, `meteor.log`, `%APPDATA%\meteor`, the pipe, the keyring service, the `dev.meteor.app` identifier, the `METEOR_*` variables). The wake phrase says the first word of `NAME` only ("OK METEOR"). The product was first built as Lintel (slug `lintel`): the one-time copy below also takes a `lintel` settings folder and its saved keys over, and an agent entry written by the old `lintel-hook` is not recognised as this build's, so disconnect an agent in the old build (or uninstall it) first. The upstream project's addresses (the repository, the website, the winget id `ShakibBinKabir.Lintel`) keep the name they have.

**Where the name lives.**

1. `crates/brand/src/lib.rs`: `NAME = "METEOR V1"`, `SLUG = "meteor"`, `HOOK_BIN = "meteor-hook"`, `HOOK_EXE = "meteor-hook.exe"`. They feed the relay pipe (`\\.\pipe\meteor-<sid>`), the data folders (`%APPDATA%\meteor`, `%LOCALAPPDATA%\meteor`), the keyring service, the hook marker, the log file (`meteor.log`), the `User-Agent`, the tray, the window titles, the plugin file names written into other tools' folders, and the wake phrase ("OK METEOR V1").
2. `src/core/brand.ts`: `BRAND = { name: "METEOR V1", slug: "meteor" }`: localStorage keys, the web-message name, the Settings title, the recap footer, the `{app}` placeholder of every string.
3. The files that cannot read a constant: `src-tauri/tauri.conf.json` (`productName` "METEOR V1", `identifier` `dev.meteor.app`, the window title, the resource `meteor-hook.exe`), `src-tauri/tauri.helper.conf.json`, `package.json`, `scripts/pack.mjs` (`meteor-<version>-setup.exe`), `src-tauri/nsis/hooks.nsh`, `src-tauri/sparse/`, and the three packages that produce a program: `meteor` (`meteor.exe`), `meteor-hook` (`meteor-hook.exe`), `meteor-speak` (`meteor-speak.exe`), with `helper/meteor-hw.csproj` (`meteor-hw.exe`, pipe `\\.\pipe\meteor-hw-<userSid>-<random>`).

Also renamed: the environment variables (`METEOR_ANTHROPIC_BASE_URL`, and the debug-only `METEOR_VOICE_MUTE`, `METEOR_VOICE_CLIPS`, `METEOR_LINK_DIR`, `METEOR_CLI_STAND_IN`, `METEOR_MIGRATE_KEYS`; `METEOR_HOOK` for `scripts/fake-session.mjs`) and the fields the relay adds to a payload (`meteor_agent`, `meteor_truncated`, `meteor_diff_truncated`). The wake phrase is built from `NAME`, so it became "OK METEOR V1"; its table of mishearings is per name and has not been measured for this one yet (`crates/voice/src/wakephrase.rs`).

**What kept its internal name.** Renaming these changes nothing a user or Windows sees: the crate and library names (`notch-feat-*`, `notch-core`, `notch-brand`, `notch_lib`, `svc-*`), the C# namespace `NotchHw`, the NSIS variables of `hooks.nsh`, the layout constants `NOTCH_W` and `NOTCH_H`, the settings keys `showPlanInNotch` and `showCodexPlanInNotch`, CSS prefixes and test names. The word "notch" also stays wherever it is the ordinary word for the thing at the top of a screen. The repository address in `crates/apps/src/lib.rs` (`REPO`: the release feed and the feedback link) is the address the repository had when 1.0.0 was built.

**The one-time copy** (`crates/core/src/migrate.rs`, called first in `run()`). At the first start, when `%APPDATA%\meteor` does not exist and a code-named folder (`%APPDATA%\notch` or `%LOCALAPPDATA%\notch`) does, the user's files are copied over: the settings folder (without the start counter), and the data folder without the old programs (`*.exe`, `*.dll`), `bin`, `speak`, `licenses`, `LICENSE`, `NOTICE.md` and the log. The saved keys the product knows (`secrets::KNOWN_KEYS`) are copied from the old keyring service to the new one, never over a key that is already there. One log line says what was copied. Nothing is moved or deleted, so the old install keeps working until the user removes it, and nothing is copied when METEOR V1's settings folder already exists. The agents' hooks are not touched: the user connects the agents in METEOR V1 through the usual diff and confirmation, and the old program's uninstaller removes the old entries. A later version may drop this step.

`scripts/check-brand.mjs` guards against the upstream names (§12, `CLAUDE.md`).
